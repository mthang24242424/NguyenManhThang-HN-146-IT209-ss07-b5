# Bài 5: Chẩn đoán và xử lý xung đột cổng mạng (Address Already in Use)

## Mục tiêu

- Thành thạo kỹ năng chẩn đoán trạng thái các cổng mạng đang lắng nghe (listening ports) trên hệ thống Linux.
- Sử dụng các lệnh quản lý tiến trình (`ps`, `kill`) để giải phóng tài nguyên bị chiếm dụng.
- Xử lý sự cố lỗi thường gặp `Address already in use` khi deploy ứng dụng.

---

## Bối cảnh

Khi khởi chạy ứng dụng Spring Boot trên cổng `8082`, hệ thống báo lỗi:

```
Web server failed to start. Port 8082 was already in use.
```

Nguyên nhân: một tiến trình khác đang chạy ngầm và chiếm giữ cổng `8082`. Cần tìm và tắt tiến trình đó để giải phóng cổng.

---

## Quy trình xử lý

### Bước 1: Giả lập cổng 8082 bị chiếm dụng

Chạy lệnh sau để giả lập một tiến trình đang chiếm cổng `8082`:

```bash
python3 -m http.server 8082 > /dev/null 2>&1 &
```

> Nếu không có `python3`, dùng thay thế:
> ```bash
> nc -l 8082 > /dev/null 2>&1 &
> ```

Lệnh này khởi động một HTTP server đơn giản lắng nghe trên cổng 8082, chạy nền (`&`) và tắt toàn bộ output (`> /dev/null 2>&1`).

---

### Bước 2: Chẩn đoán tiến trình đang chiếm cổng 8082

Sử dụng công cụ `ss` để xem tiến trình nào đang giữ cổng:

```bash
sudo ss -tlnp | grep 8082
```

Hoặc dùng `lsof`:

```bash
sudo lsof -i :8082
```

**Kết quả mẫu (ss):**

```
LISTEN  0  5  0.0.0.0:8082  0.0.0.0:*  users:(("python3",pid=12345,fd=3))
```

**Kết quả mẫu (lsof):**

```
COMMAND   PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
python3 12345 user    3u  IPv4  98765      0t0  TCP *:8082 (LISTEN)
```

→ **PID của tiến trình giả lập: `12345`** (ví dụ minh họa)

Kiểm tra thêm thông tin tiến trình bằng `ps`:

```bash
ps -p 12345 -f
```

Kết quả mẫu:

```
UID        PID  PPID  C STIME TTY          TIME CMD
user     12345  1234  0 10:00 ?        00:00:00 python3 -m http.server 8082
```

---

### Bước 3: Ghi lại thông tin tiến trình

| Thông tin       | Giá trị                              |
|-----------------|--------------------------------------|
| PID             | `12345`                              |
| Tên tiến trình  | `python3`                            |
| Lệnh đầy đủ     | `python3 -m http.server 8082`        |
| Cổng chiếm dụng | `8082`                               |
| Trạng thái      | `LISTEN`                             |

---

### Bước 4: Kết thúc tiến trình chiếm cổng

Dùng `kill` thông thường trước:

```bash
kill 12345
```

Nếu tiến trình không dừng (kiểm tra lại bằng `ss` hoặc `lsof`), dùng `kill -9` để buộc dừng:

```bash
kill -9 12345
```

Xác nhận tiến trình đã bị tắt:

```bash
sudo ss -tlnp | grep 8082
# Không có output → cổng 8082 đã được giải phóng
```

---

### Bước 5: Khởi động lại dịch vụ Spring Boot

Khởi động lại `spring-app.service` (đã được tạo ở EX3):

```bash
sudo systemctl restart spring-app.service
```

Kiểm tra trạng thái dịch vụ:

```bash
sudo systemctl status spring-app.service
```

Kết quả mong đợi:

```
● spring-app.service - Spring Boot Application
     Loaded: loaded (/etc/systemd/system/spring-app.service; enabled)
     Active: active (running) since ...
```

---

### Bước 6: Xác nhận cổng 8082 do Java quản lý

```bash
sudo ss -tlnp | grep 8082
```

Hoặc:

```bash
sudo lsof -i :8082
```

**Kết quả mong đợi:**

```
LISTEN  0  100  0.0.0.0:8082  0.0.0.0:*  users:(("java",pid=99999,fd=10))
```

→ Cổng `8082` hiện đang được lắng nghe bởi tiến trình `java` (chạy `app.jar`), không còn là tiến trình giả lập `python3`.

---

## Tổng kết quy trình

```
1. Phát hiện xung đột cổng
        ↓
2. ss -tlnp / lsof -i :8082   →  Tìm PID chiếm cổng
        ↓
3. ps -p <PID> -f              →  Xác nhận thông tin tiến trình
        ↓
4. kill <PID> / kill -9 <PID>  →  Giải phóng cổng
        ↓
5. systemctl restart spring-app.service  →  Khởi động lại ứng dụng
        ↓
6. ss -tlnp | grep 8082        →  Xác nhận java đang giữ cổng
```

---

## Giải thích các lệnh sử dụng

| Lệnh | Ý nghĩa |
|------|---------|
| `ss -tlnp` | Liệt kê các TCP socket đang LISTEN, hiển thị PID/tên tiến trình |
| `lsof -i :8082` | Hiển thị tiến trình đang mở kết nối mạng trên cổng 8082 |
| `ps -p <PID> -f` | Xem thông tin chi tiết của tiến trình theo PID |
| `kill <PID>` | Gửi tín hiệu SIGTERM (dừng nhẹ nhàng) tới tiến trình |
| `kill -9 <PID>` | Gửi tín hiệu SIGKILL (buộc dừng ngay lập tức) tới tiến trình |
| `systemctl restart` | Khởi động lại một systemd service |
| `systemctl status` | Xem trạng thái hiện tại của một systemd service |

---

## Lưu ý

- **Ưu tiên dùng `kill` trước `kill -9`**: `kill -9` bỏ qua toàn bộ signal handler, tiến trình không có cơ hội dọn dẹp tài nguyên.
- **Cẩn thận với PID**: luôn xác nhận đúng tiến trình qua `ps` trước khi `kill` để tránh tắt nhầm tiến trình quan trọng.
- **Quyền `sudo`**: các lệnh `ss -tlnp` và `lsof` cần quyền root để hiển thị đầy đủ thông tin PID/tiến trình.
